# Haier Fridge Premium Card audit

## Scope and source

The source declares version **5.0.0**. Commit `421c542` preserves the original JavaScript unchanged. Commit `2cfa8df` adds the offline preview, documentation and initial characterization checks. The working source now includes an English/German localization pass requested after that audit; the change does not alter the card's visual styling.

The card reads five configured Home Assistant entities: fridge target temperature, My Zone target, freezer target, humidity and fridge door state. It displays an inline SVG illustration, five value tiles, door/connection status, a relative last-updated label and a history button. It supports container-width layout classes, door animation and `prefers-reduced-motion`. `getCardSize()` returns 8.

Configuration options are `title`, `model`, `entity_fridge_target`, `entity_my_zone_target`, `entity_freezer_target`, `entity_humidity`, `entity_door_fridge`, `show_history_button`, `show_last_updated` and `animate`. Legacy entity aliases are `fridge_entity`, `my_zone_entity`, `freezer_entity`, `humidity_entity` and `door_entity`. `getStubConfig()` proposes a model-specific set of IDs and looks for German name fragments. It selects the first matching entity ID without checking its device or unit. This is a setup limitation for users with other models or naming conventions.

## Language behavior

The card reads Home Assistant's `hass.language`. German (`de`, including regional forms such as `de-DE`) displays German labels; all other and missing language values use English. This follows Home Assistant's documented effective frontend language property in its [frontend type definition](https://github.com/home-assistant/frontend/blob/dev/src/types.ts). Changing the HA language causes the card to rerender its localized labels. Default titles generated by the card follow the selected language; custom titles remain as configured. Temperature and numeric humidity display use a German decimal comma or English decimal point. The editor labels use the same language.

Only English and German translations are included. Other languages fall back to English. User-defined titles and model strings are intentionally not translated. The relative-time messages are translated for the current minute/hour/day ranges; the display refreshes only when Home Assistant sends a new state update.

## Home Assistant behavior and states

The card reads `hass.states` and reads units from `attributes.unit_of_measurement`; temperature falls back to `°C` and humidity to `%`. It treats `unknown`, `unavailable`, `none`, an empty string and missing entity state as unavailable. Door values `on`, `open`, `true`, `1`, `offen` and `opened` mean open; another known value means closed. If any configured entity is available the card says connected, even if the other entities are missing. If none are available it shows the no-data message.

Temperatures use `parseFloat`, which accepts a numeric prefix in a longer string. An invalid timestamp can produce a `NaN` relative-time message. These are existing data-validation limitations. There are no timers or intervals.

The code does not call HA services, APIs or raw network functions. Clicking an entity tile emits `hass-more-info`; the history button updates the HA history route and emits `location-changed`. A real HA dashboard handles those events/navigation. In the isolated preview, the fixture records them locally. Its `callService` mock records any call; other mocked HA APIs reject calls.

The illustration is inline SVG, and CSS is embedded. There are no remote images, fonts or runtime libraries. The real card relies on HA's `ha-icon` and editor custom elements. The preview replaces icons with local placeholders and does not load HA's editor components. The checked-in fixture uses only fictional `demo_*` entity IDs; the source scan found no tokens, personal IDs or private addresses.

## DOM and configuration editor

The card uses light DOM and `innerHTML` for a full render, escaping configured titles, model text and entity IDs where they enter markup. Ordinary HA state updates update the existing value elements without replacing the card DOM. Entity tiles and the history button each receive one click listener. A `ResizeObserver` is disconnected when the card is removed.

The editor provides title/model text fields, five entity pickers (three `number`, one `sensor`, one `binary_sensor`) and switches for animation, history and last-updated display. It emits `config-changed`. The editor rebuilds all of its `innerHTML` on each HA update, which can replace focused or edited fields. It also has a possible initialization-order issue when `hass` arrives before `setConfig`. This pass did not include a full-HA editor test, so that lifecycle path remains a known risk and should be addressed before release.

## Checks performed

After adding locale selection, the small browser suite was run in isolated Chromium. It covers normal state, open door, missing entities, state updates, each of the five tile clicks, one history click, service-call counts, runtime errors and English/German UI behavior at desktop (1440×1000) and mobile (390×844) viewports. Each tile emitted exactly one `hass-more-info` event with the configured entity ID; history emitted one expected path change. The mock recorded zero service calls. The fixture verified English labels/decimal points, German labels/decimal commas, default titles in both languages and German editor labels. The desktop and mobile checks use Chromium viewport emulation, not physical hardware.

The runner serves only inspected local files under a virtual origin, disables service workers and aborts all other browser requests. A separate inert navigation probe confirmed that an unmatched request is intercepted. The page's Content Security Policy and browser guards block common network APIs. The preview does not use a live HA connection.

Machine-readable results, including source and suite fingerprints, and screenshots are in the ignored local `test-results/` directory. These runtime artifacts are not committed.

## Not checked

No real Home Assistant frontend, Haier integration, device, service, `hass-more-info` dialog or history page was used. The HA editor components were not loaded; synthetic fixture labels do not prove their live behavior. No physical phone/touch interaction, screen reader, full accessibility audit, other refrigerator model or third-party entity naming convention was tested. The tests do not cover invalid values/timestamps, elapsed-time refresh, every responsive breakpoint, or all state combinations. HACS requirements, CI and release packaging have not been validated.

## Release blockers and open decisions

- Test the editor in the target HA frontend and fix its update/lifecycle behavior.
- Replace model- and German-name-specific entity suggestions with a setup path that works for different models and names.
- Decide whether partial availability should have a more precise status message.
- Consider stricter validation for numeric states and timestamps, and whether the relative time should refresh without HA updates.
- Verify behavior against the intended Home Assistant versions and integrations before claiming compatibility.
- Confirm code/artwork/brand rights and have the project owner choose a license. No license has been added.

This audit was completed before publication. The owner subsequently authorized publication of v5.0.0-beta.1 with the limitations above disclosed.
